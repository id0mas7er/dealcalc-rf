# DealCalc RF — расчёты для оценщика в России, доступные ИИ-агенту

DealCalc RF — открытая Python-библиотека и локальный MCP-сервер с расчётами
для оценочной деятельности в Российской Федерации: недвижимость, бизнес,
машины и оборудование, автомобили. ИИ-агент (например, Claude) вызывает эти
расчёты как инструменты, а оценщик получает черновик: каждую корректировку,
вес и формулу видно, ссылка на стандарт приложена, а проблемные данные
помечены.

## Зачем это нужно

Языковая модель хорошо читает задание, ищет аналоги и пишет текст, но для
расчётов стоимости она ненадёжна:

- ошибается в арифметике на длинных цепочках корректировок и
  дисконтировании;
- не всегда показывает промежуточные шаги, поэтому результат нельзя
  проверить;
- может «подставить» коэффициент или ставку, которые никто не обосновывал;
- путает методики и не отличает норму ФСО от частной рекомендации.

DealCalc RF разделяет работу: **агент собирает данные и рассуждает, числа
считает проверенный код, решения принимает оценщик.** Каждая функция
возвращает не просто число, а результат с исходными данными, всеми
промежуточными шагами, карточкой метода (стандарт, формула, источник) и
списком замечаний, которые оценщик должен проверить.

## С чего начать

- **Оценщику** — [гайд для оценщика](docs/appraiser-guide.md): что делать,
  какие данные давать, что писать агенту, как читать результат, готовые
  запросы и чек-лист перед отчётом.
- **Тому, кто подключает агента**, — [инструкция для агента](docs/agent-guide.md):
  установка, подключение к Claude Code, Claude Desktop и Codex, правила
  работы агента.
- **Методы и формулы** — [описание российского профиля](docs/russia.md).

## Для кого

- **Оценщики** — черновые расчёты по ФСО с прозрачными корректировками,
  проверка задания на оценку, импорт аналогов из выгрузок площадок.
- **Разработчики инструментов для оценки** — готовый расчётный слой и
  MCP-сервер, который подключается к ИИ-агенту без собственного бэкенда.
- **Банки, залоговые и юридические службы** — быстрая предварительная
  оценка с понятным происхождением каждого числа (не заменяет отчёт).
- **Студенты и преподаватели** — формулы ФСО и методических рекомендаций
  в исполняемом виде с пошаговым разбором.

## Как это работает

```text
Оценщик ──задание──▶ ИИ-агент ──вызов инструмента──▶ MCP-сервер DealCalc RF
                        ▲                                    │
                        │                          библиотека dealcalc.rf
                        │                                    │
                        └──── черновик: шаги, формула, ◀─────┘
                              стандарт, замечания
Оценщик проверяет черновик и принимает решения (веса, ставки, коэффициенты).
```

Сервер работает **локально** по stdio: без хостинга, без отправки данных в
сеть и без обращения к внешним сервисам. Данные об аналогах загружаются из
файлов пользователя (CSV, JSON, JSONL).

## Принципы

1. **Результат — всегда черновик.** Библиотека не формирует отчёт об оценке
   и не подтверждает его соответствие ФСО. Статусы результата:
   «черновой расчёт», «нужна проверка оценщика», «недостаточно данных»,
   «расчёт выполнен — согласование не автоматизировано».
2. **Коэффициенты задаёт оценщик.** Скидки на торг, ставки, веса подходов
   и ограничения отбора аналогов не подставляются по умолчанию — их нужно
   передать явно и обосновать. Единственное значение по умолчанию — порог
   существенного расхождения подходов при согласовании: более 30 %
   (оценщик может задать свой).
3. **Каждый шаг виден.** Корректировки применяются по порядку, у каждой —
   цена до и после; показываются валовая и итоговая корректировки, доли
   весов, коэффициент вариации выборки.
4. **Факты отдельно от напоминаний.** `checks` — проблемы данных (нет
   источника или даты цены, неоднородная выборка, расхождение НДС); они
   переводят результат в статус «нужна проверка оценщика». `guardrails` —
   методические напоминания; статус они не меняют.
5. **Контекст задания в каждом расчёте.** Дата оценки, вид стоимости,
   признак и ставка НДС, номер задания (`context`) возвращаются в результате
   и сверяются с расчётом.
6. **Ясные рамки.** ФСО I–VI (включая требования к отчёту), ФСО №7 (недвижимость), ФСО №8 (бизнес),
   ФСО №10 (машины и оборудование), методические рекомендации
   «СРОО Экспертный совет», методика Козлова В.В. и Фролова И.С. для машин и
   оборудования. ФСО №9 (залог), методика Минюста 2018 года и ВСН 53-86(р) в
   проект не входят.

## Пример

```python
from dealcalc.rf import comparative_approach

result = comparative_approach(
    subject_area_sqm=54,
    comparables=[
        {"price": 9_800_000, "area_sqm": 52, "source": "ЦИАН",
         "date": "2026-09-20", "price_type": "предложение",
         "adjustments": [
             {"name": "Скидка на торг", "type": "pct", "value": -5},
             {"name": "Этаж", "type": "pct", "value": 2},
         ]},
        {"price": 10_400_000, "area_sqm": 56, "source": "Avito",
         "date": "2026-09-25", "price_type": "предложение",
         "adjustments": [{"name": "Скидка на торг", "type": "pct", "value": -5}]},
    ],
    context={"valuation_date": "2026-10-01", "value_type": "рыночная",
             "vat": "not_applicable"},
)
```

Сокращённый результат:

```text
status            черновой расчёт
indicated_value   9 694 290,60 руб.   (179 523,90 руб./м² × 54 м²)
comparables[0]    188 461,54 → торг −5 % → 179 038,46 → этаж +2 % → 182 619,23 руб./м²
method_card       ФСО V; ФСО №7, п. 22 — формула и ссылка на стандарт
guardrails        аналоги 1, 2 — цены предложения: обоснуйте скидку к цене сделки
checks            []
```

Учебные данные. Скидку на торг и корректировки задаёт и обосновывает
оценщик.

## Что умеет

| Область | Расчёты | Основание |
|---|---|---|
| Задание и отчёт | проверка состава задания до расчёта (`check_assignment`); проверка отчёта перед подписанием (`check_report`): 15 сведений п. 7, источники с датами, подпись, расчёты без нерешённых замечаний | ФСО II–IV; ФСО VI |
| Недвижимость: сравнительный подход | цена за м² с пошаговыми корректировками (процент, группа процентов, абсолютная, коэффициент торможения, износ), веса аналогов, однородность выборки | ФСО V; ФСО №7, п. 22 |
| Недвижимость: доходный подход | ПВД → ДВД → ЧОД, ставка капитализации по рынку, прямая капитализация, ВРМ, ДДП, модель Гордона, реверсия, кумулятивная ставка, норма возврата капитала (Ринг, Инвуд, Хоскольд) с долей изменения стоимости, NPV, IRR | ФСО V, пп. 14, 15, 21; ФСО №7, п. 23 |
| Недвижимость: затратный подход | затраты на замещение по цепочке индексов, прибыль предпринимателя, физический, функциональный и внешний износ | ФСО V, пп. 24, 31, 33; ФСО №7, п. 24 |
| Согласование и ликвидация | согласование подходов с весами оценщика и порогом существенного расхождения (по умолчанию более 30 %), ликвидационная стоимость объекта (срок экспозиции и скидка на вынужденность продажи) | ФСО V, п. 3; ФСО II |
| Бизнес | ДДП по собственному или инвестированному капиталу, мультипликаторы, чистые активы, ликвидация, действительная стоимость доли участника ООО, отложенные налоги, переход к стоимости доли | ФСО №8; закон № 14-ФЗ |
| Машины и оборудование | коэффициент торможения, цена единицы параметра, индексный метод, физический износ, утилизация, цена и себестоимость с НДС, качественные корректировки | ФСО №10; Козлов В.В., Фролов И.С. |
| Автомобили | подбор аналогов по марке и модели (словарь написаний, транслитерация), отбор по году и пробегу, корректировки, взвешенная медиана | ФСО V; ФСО №10, п. 13 |
| Рекомендации «СРОО Экспертный совет» | рыночная аренда (затратно-компенсационная модель), аренда места под сотовую связь, внешнее обесценение (три способа), паи ПИФ; у каждой модели — условия применения, которые подтверждает оценщик | МР и МРз Экспертного совета |
| Импорт аналогов | CSV, JSON, JSONL, Excel с русскими названиями колонок; продажа недвижимости и автомобилей, аренда, доходные объекты, компании-аналоги, машины; цены «12 500 000 ₽», «5 млн руб.»; дата и тип цены; дедупликация | — |

Полное описание методов, формул и ссылок на документы —
в [docs/russia.md](docs/russia.md).

## Быстрый старт

Нужен Python 3.9 или новее; для MCP-сервера — 3.10 или новее.

```bash
git clone https://github.com/id0mas7er/dealcalc-rf.git
cd dealcalc-rf
pip install -e .            # библиотека
pip install -e ".[mcp]"     # плюс MCP-сервер для ИИ-агента
```

### Подключение к Claude

Claude Code — одной командой:

```bash
claude mcp add dealcalc-rf -- python /absolute/path/to/dealcalc-rf/mcp_server/server.py
```

Claude Desktop — в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "dealcalc-rf": {
      "command": "python",
      "args": ["/absolute/path/to/dealcalc-rf/mcp_server/server.py"]
    }
  }
}
```

После подключения агенту доступны 44 инструмента с описаниями на русском,
а сервер сам передаёт агенту краткие правила работы. Подключение Codex,
проверка установки, порядок работы агента, сценарии по видам объектов и
разбор полей результата — в [инструкции для агента](docs/agent-guide.md).

### Импорт объявлений

```python
from dealcalc.rf import load_listings, vehicle_comparative_approach

analogs = load_listings("автомобили.csv", source="Avito", listing_type="vehicle")
result = vehicle_comparative_approach(
    {"brand": "Лада", "model": "Веста", "year": 2021, "mileage_km": 60_000},
    analogs,
    max_year_diff=2,
    max_mileage_diff=40_000,
)
```

Импорт читает CSV, JSON, JSONL и Excel (`.xlsx`, лист — параметром
`sheet`), понимает русские названия колонок, разделители разрядов и
десятичную запятую, «тыс.» и «млн», дату публикации (дату цены), тип цены
(по умолчанию «предложение») и признак НДС цены, удаляет дубли. Ошибка в строке файла называет
её номер. Аналоги передаются в расчёты как есть.

| `listing_type` | Что импортируется | Обязательно | Для расчёта |
|---|---|---|---|
| `property` | продажа недвижимости | цена | `comparative_approach` |
| `vehicle` | продажа автомобилей | цена; для подбора — марка и модель | `vehicle_comparative_approach` |
| `rent` | аренда помещений | арендная плата (или цена) либо ставка за м² с площадью; период «месяц» или «год» — колонкой «период» или параметром `rent_period`, без умолчания | `comparative_approach` по годовой аренде в `price_rub` |
| `income` | доходные объекты | цена и ЧОД и/или валовой доход | `cap_rate_extraction`, `gross_rent_multiplier` |
| `business` | компании-аналоги | стоимость (`value`) и показатель (`metric`); наименование, отрасль | `business_multiples` |
| `machinery` | машины и оборудование | цена; наименование, марка, модель, год, наработка | `qualitative_adjustments`, анализ параметров |

Сбор объявлений напрямую с площадок не реализован: используются файлы,
которые сохранил пользователь. Живой поиск по ссылке на выдачу и разбор
сохранённых страниц доступны в приватном дополнении dealcalc-rf-collect
(доступ — у автора проекта).

## Единицы

Суммы — в рублях (поле `currency` по умолчанию `RUB`), площадь — в м²,
ставки, доли и корректировки — в процентах: `5` означает 5 %. Копейки
округляются «половина вверх», промежуточные величины не округляются.

## Чего проект не делает

- Не составляет и не подписывает отчёт об оценке (только проверяет его состав
  по ФСО VI), не заменяет оценщика и
  его профессиональное суждение.
- Не выбирает за оценщика ставки, коэффициенты, веса и аналоги.
- Не обращается к сети: нет парсеров площадок, справочников и котировок.
- Не охватывает ФСО №9, методику Минюста 2018 года и ВСН 53-86(р).

## Качество

- 300+ автоматических тестов (`pytest`), в том числе на каждое замечание
  внешних ревью.
- Пять внешних ревью кода и методики, включая полный аудит кода силами
  Codex; все подтверждённые замечания исправлены и описаны в
  [CHANGELOG](CHANGELOG.md).
- Пункты ФСО в карточках методов сверены с текстами стандартов на сайте
  «СРОО Экспертный совет»; формулы машин и оборудования — с первоисточником.

```bash
pip install -e ".[dev]"
pytest
```

## Совместимость версий

Версия 0.4.0 изменила поля результата. Агентам и программам, которые
работали с 0.3.x, нужно учесть:

- `reconciled_value` может быть `null`: при расхождении подходов выше
  порога без обоснования итоговой стоимости нет, число в
  `weighted_value_diagnostic` — только диагностика;
- `indicated_value_range` → `analogs_spread`, `value_range` →
  `approaches_spread` (это разброс, а не интервал стоимости; интервал —
  `value_interval` от оценщика);
- `variation.homogeneous` → `variation.within_threshold`;
- `residual_value` больше не прибавляет утилизацию к остатку.

Полный перечень — в [CHANGELOG](CHANGELOG.md).

Версия 0.7.0 ничего не ломает: новые шаги корректировок (`coef`, `ratio`),
границы справочника (`range`, `source_ranges`) и правила весов
(`count_share`, `gross_share`) необязательны.
