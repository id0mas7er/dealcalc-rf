# Инструкция для ИИ-агента: подключение и работа с DealCalc RF

Документ для агента (Claude, Codex и др.) и для человека, который его
настраивает. Оценщику, который работает с агентом, —
[гайд для оценщика](appraiser-guide.md). Первая часть — как подключить MCP-сервер, вторая — как с ним
работать при подготовке расчётов для оценщика.

Краткая версия правил из второй части передаётся агенту автоматически при
подключении (инструкции MCP-сервера).

---

## Часть 1. Подключение

### Требования

- Python 3.10 или новее для MCP-сервера (этого требует пакет `mcp`);
  сама библиотека работает и на 3.9.
- Пакет `mcp` версии 1.x (ставится вместе с `.[mcp]`; в SDK 2.x нет
  используемого API `FastMCP`).
- Сеть для работы сервера не нужна: он запускается локально по stdio.

### Установка

```bash
git clone https://github.com/id0mas7er/dealcalc-rf.git
cd dealcalc-rf
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[mcp]"     # Windows
# .venv/bin/python -m pip install -e ".[mcp]"       # Linux, macOS
```

В командах ниже `PYTHON` — полный путь к Python из виртуального окружения
(`D:\...\dealcalc-rf\.venv\Scripts\python.exe` в Windows), `SERVER` — полный
путь к `mcp_server/server.py`. Используйте абсолютные пути: агент запускает
сервер из своей рабочей папки.

### Claude Code

```bash
claude mcp add dealcalc-rf -- PYTHON SERVER
```

или файл `.mcp.json` в корне проекта, где работает агент:

```json
{
  "mcpServers": {
    "dealcalc-rf": {
      "command": "PYTHON",
      "args": ["SERVER"]
    }
  }
}
```

### Claude Desktop

Тот же блок `mcpServers` — в `claude_desktop_config.json`
(Windows: `%APPDATA%\Claude\claude_desktop_config.json`; macOS:
`~/Library/Application Support/Claude/claude_desktop_config.json`).
После правки перезапустите приложение.

### Codex

```bash
codex mcp add dealcalc-rf -- PYTHON SERVER
```

### Проверка подключения

1. Список инструментов сервера `dealcalc-rf` — 44 инструмента с префиксом
   `rf_`.
2. Пробный вызов `rf_income_capitalization` с `noi_annual=1000000` и
   `cap_rate_pct=10` возвращает `indicated_value = 10000000` и
   `status = "черновой расчёт"`.

Если инструментов нет: проверьте, что путь к Python ведёт в окружение с
установленным `mcp` 1.x, и запустите `PYTHON SERVER` вручную — ошибка
импорта будет видна в консоли (без ошибок сервер молча ждёт запросов;
остановить — Ctrl+C).

Клиент может спрашивать разрешение на вызов каждого инструмента — это
нормально: инструменты только считают и читают указанные локальные файлы.
В Codex вызовы инструментов этого сервера можно разрешить заранее
параметром `default_tools_approval_mode = "approve"` в разделе
`[mcp_servers.dealcalc-rf]` файла `~/.codex/config.toml`.

Порядок проверен: свежий клон с GitHub, установка по шагам выше,
регистрация командой `codex mcp add`, затем агент Codex увидел все
инструмента, получил правила сервера и выполнил пробные расчёты.

## Часть 2. Как работать

### Роли

- **Оценщик** даёт задание, выбирает аналоги, коэффициенты, ставки и веса,
  подписывает отчёт.
- **Агент** собирает и структурирует данные, вызывает инструменты,
  объясняет результат и перечисляет, что оценщику нужно проверить.
- **DealCalc RF** считает числа и сообщает, на чём расчёт держится.

Результат инструмента — всегда черновик. Агент не выдаёт его за итоговую
стоимость и не переносит в отчёт без проверки оценщиком.

### Порядок работы

1. **Проверить задание** — `rf_check_assignment`. Обязательные сведения:
   `object_description` (объект), `rights` (права), `purpose` (цель),
   `value_type` (рыночная, инвестиционная, равновесная, ликвидационная),
   `value_premises` (предпосылки), `valuation_date` (ГГГГ-ММ-ДД), а также
   `object_type`: `real_estate`, `business`, `machinery` или `vehicle`. Если
   `can_proceed = false`, расчёт не начинать — запросить у оценщика
   недостающее (`missing_critical`).
2. **Собрать контекст** для всех расчётов:
   `{"valuation_date": "2026-10-01", "value_type": "рыночная", "vat":
   "excluded", "vat_rate_pct": 22, "assignment_id": "ОЦ-15/2026"}`. `vat`:
   `included` (с НДС), `excluded` (без НДС), `not_applicable`. Передавать
   `context` в каждый расчёт стоимости.
3. **Загрузить аналоги**, если они в файле, — `rf_load_listings` (CSV, JSON,
   JSONL, Excel с параметром `sheet`; `listing_type`: `property`, `vehicle`,
   `rent` — период аренды спросить у оценщика, если его нет в файле,
   `income`, `business`, `machinery`). Аналоги передаются в расчёт как есть.
4. **Получить от оценщика параметры**, которые код не подставляет: скидку на
   торг и другие корректировки, ставки, веса аналогов и подходов,
   ограничения отбора автомобилей. Если оценщик их не дал — спросить, а не
   придумывать. Порог существенного расхождения подходов по умолчанию —
   более 30 %; другой порог — только по указанию оценщика.
5. **Посчитать подходы** — нужные инструменты ниже.
6. **Согласовать** — `rf_reconcile_approaches` с весами оценщика; порог —
   30 % по умолчанию или заданный оценщиком.
7. **Описать базу потока и ставки** в доходных расчётах (`flow_rate_basis`) и
   передать условия применения моделей СРО, которые подтвердил оценщик
   (`confirmed_conditions`); сам агент условия не подтверждает.
8. **Перед подписанием отчёта** — `rf_check_report` (ФСО VI) с расчётами в
   `approaches.calculations`.
9. **Доложить**: стоимость, разброс аналогов и подходов (это не интервал
   стоимости — интервал определяет оценщик), статус, все `checks` (что исправить
   в данных), все `guardrails` (что обосновать в отчёте), стандарт и формулу
   из `method_card`.

### Обязательные правила

- Не подставлять коэффициенты, ставки, скидки и веса «по умолчанию» или
  «по рынку» без указания оценщика или источника. Предлагать значение можно
  только с источником и явной пометкой, что выбор за оценщиком.
- Не пересчитывать числа самостоятельно и не «исправлять» результат
  инструмента — при сомнении вызвать инструмент повторно с другими данными.
- Не скрывать `checks` и `guardrails` и не пересказывать их как
  несущественные.
- Указывать происхождение аналогов: `source`, `date` (дата цены, а не дата
  сбора), `price_type` (`сделка` или `предложение`), при наличии — `url`,
  `conditions`, `reliability`.
- Корректировки задавать шагами по порядку; скидку на торг ставить первой.
- Значение из справочника передавать с `source`, `date`, `page` и границами
  справочника: `range` у шага корректировки, `source_ranges` у ставок,
  сроков и долей. Числа справочников в DealCalc RF не встроены — их даёт
  оценщик или его каталог справочников; что куда передавать — в
  [гайде оценщика](appraiser-guide.md#данные-справочников-что-и-куда).
- Справочник — по категории объекта (сельхозземли, производственно-складская,
  офисная — свои сборники; АБН-Консалт — только Москва и Московская
  область; СтатРиелт — для всех своих категорий с градацией группы),
  последний выпуск, вышедший к дате оценки. В `range` передавать `mean`,
  расширенный интервал, если он есть, и `kind`: `confidence` — если `low` /
  `high` — доверительный интервал среднего (Лейфер), иначе `values`. По
  умолчанию берётся среднее; поправка больше 30 % — замечание о
  сопоставимости аналога. Правило минимальной поправки
  (`"choice_rule": "minimal"`) и каскад `staged` — только если их выбрал
  оценщик.
- Поправка на площадь по уравнениям регрессии по практике оценщика — шаг
  `staged` с этапами: уравнение среднего значения → уравнения нижней и
  верхней границы расширенного интервала (не доверительного) → таблица
  соотношения площадей группы городов. Код берёт первый этап с поправкой до
  30 % среди уравнений в их области применимости, иначе наименьшую; для неё
  нужен комментарий оценщика (`justification`).
- В `rf_check_report`: `final_value` должен совпадать с результатом расчёта
  или согласования (до 1 % на округление) либо переход объясняется в
  `final_value_justification`; `assignment.assignment_id` — тот же, что в
  `context` расчётов.
- Граница применимости уравнения из справочника («на исходных данных до
  N кв.м») — `domain` у шага или варианта `param`. Доли операционных расходов
  из справочника (доля ПВД) — статья `pct` с `"base": "pgi"`, интервал —
  `range` у статьи. Числа из OCR-копий справочников сверять с оригиналом.
- Не применять методы вне рамок проекта (ФСО №9, методика Минюста 2018
  года, ВСН 53-86(р)) и не выдавать их результат за расчёт DealCalc RF.

### Как читать результат

| Поле | Что значит | Что делать агенту |
|---|---|---|
| `status` | «черновой расчёт» — замечаний к данным нет; «нужна проверка оценщика» — есть `checks`; «недостаточно данных»; «расчёт выполнен — согласование не автоматизировано» — расхождение подходов выше порога без обоснования | назвать статус дословно |
| `checks` | факты о данных: нет источника или даты цены, неоднородная выборка, расхождение НДС, противоречивая пара аналогов | перечислить все и предложить, как исправить данные |
| `guardrails` | методические напоминания: обосновать скидку к цене предложения, указать контекст, проверить дубли | перечислить как пункты для обоснования в отчёте |
| `method_card` | метод, стандарт и пункт, формула, статус формулы (норма ФСО или расчётное представление), ссылка | указывать при докладе |
| `context` | дата оценки, вид стоимости, НДС из задания | сверить с заданием |
| `conditions` | условия применимости метода | проверить, что они выполняются |

Ошибка инструмента (`ValueError`) — это неверные или неполные входные
данные, а не сбой: прочитать текст ошибки, исправить вход или спросить
оценщика.

### Сценарии

**Квартира, сравнительный подход.** `rf_comparative_approach`:
`subject_area_sqm` и аналоги `{price, area_sqm, source, date, price_type,
adjustments}`. Шаги `adjustments`: `{"name", "type": "pct", "value": -5}`
(процент), `pct_group` (подряд идущие суммируются), `abs` (руб./м²),
`param` (`subject`, `analog`, `exponent` — коэффициент торможения),
`coef` (`value` — коэффициент таблицы справочника), `ratio` (`subject`,
`analog` — коэффициенты к одной базе), `depreciation`. У шага — `source`,
`date`, `page` и `range` {`low`, `high`} — границы справочника. Веса —
`weighting`: `manual` (поле `weight`), `inverse_gross`, `inverse_count`,
`count_share`, `gross_share`, `gross_share_fraction` (единицы S_i — проценты
или доли — выбирает оценщик).

**Коммерческая недвижимость, доходный подход.**
`rf_net_operating_income` (ПВД → ДВД → ЧОД) → ставка: по рынку
`rf_cap_rate_extraction` или построением `rf_discount_rate_build_up` и
`rf_capital_recovery_rate` (Ринг, Инвуд, Хоскольд; `value_change_pct` — доля
изменения стоимости, важна при большой доле земли) →
`rf_income_capitalization`. Для прогноза — `rf_dcf_valuation`
(`cash_flows[0]` — первый год) с `rf_reversion_value` или
`rf_gordon_terminal_value` в `terminal_value`.

**Затратный подход.** `rf_indexed_replacement_cost` (затраты по индексам) →
`rf_cost_approach` (земля, прибыль предпринимателя, износы).

**Согласование.** `rf_reconcile_approaches`: `approach_values` и `weights`
с одинаковыми именами подходов, сумма весов 1. `max_divergence_pct` —
порог существенного расхождения: по умолчанию 30 % (существенно — более
30 %), передавать другой только по указанию оценщика. При превышении порога
нужен `justification`.

**Ликвидационная стоимость объекта.** `rf_asset_liquidation_value`: сроки
экспозиции и ставка; скидка на вынужденность продажи —
`forced_sale_discount_pct` только с `forced_sale_justification`.

**Автомобиль.** `rf_vehicle_comparative_approach`: объект
`{brand, model, year, mileage_km}`, аналоги из `rf_load_listings`,
`max_year_diff` и `max_mileage_diff` — от оценщика. Написания марок и
моделей («Лада» и «LADA», «Солярис» и «Solaris») сопоставляются
автоматически; дополнительные — `synonyms` или `synonyms_file`.

**Машины и оборудование.** `rf_braking_coefficient` по двум аналогам →
шаг `param` в корректировках; `rf_chain_index` и `rf_index_price`;
`rf_physical_depreciation`; `rf_cost_from_price` и `rf_price_from_cost` (НДС,
рентабельность); `rf_qualitative_adjustments` (нижние и верхние аналоги).

**Бизнес (ФСО №8).** `rf_business_income_approach` (`basis`: `equity` —
FCFE или `invested_capital` — FCFF), `rf_business_multiples`
(`basis` — числитель мультипликатора), `rf_net_assets`,
`rf_business_liquidation_value`, `rf_actual_share_value` (доля участника
ООО), `rf_business_interest_value` (переход к стоимости доли).

### Единицы

Суммы — рубли, площадь — м², ставки, доли и корректировки — проценты: `5`
означает 5 %, а не 0,05.

### Чего не делать

- Не называть результат «рыночной стоимостью по отчёту» — это черновой
  расчёт.
- Не выбирать за оценщика аналоги, веса, ставки и поправки.
- Не отбрасывать аналоги молча: если аналог исключён, сказать почему.
- Не считать дату сбора файла (`collected_at`) датой цены.

Подробное описание методов и формул — в [russia.md](russia.md).
